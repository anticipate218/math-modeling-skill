# 配图库：按题型选图、看效果、照规范画

本目录是 `scripts/make_figures.py` 的产物。脚本一键重生成全部 16 张图，本文件说明**每张图用在哪、两个轴各是什么、要传达什么结论、图注怎么写、别踩什么坑**。

配套代码：`scripts/make_figures.py`（约 2000 行，仅依赖 `numpy` + `matplotlib`）。

**数据全部是脚本自己造的**（正态/均匀随机数、解析式合成场、固定随机种子 `20240517`），不含任何真实统计年鉴、真实地理位置或他人实验数据。因此这些图适合作为：

### 1.1 为什么本仓库不放官方优秀论文里的图

这是三条独立的理由，任何一条都足以否决"从优秀论文里截图当参考图/直接复用"的做法：

1. **版权**。论文插图是作者的受保护作品。竞赛主办方公开论文用于交流，**不等于**授予了转载、再分发或商业使用的许可；本仓库以 MIT 许可发布，无法收录版权状态不明的第三方图片。仓库根目录的写作约定也明确要求"禁止转载版权材料"。
2. **学术不端风险**。即使是"参考"，把他人论文中的图（哪怕改了配色）放进自己的参赛论文，评阅中可被认定为抄袭；反之，若只是"看图找灵感"然后自己用工具重画，则是完全正当的学习方式。本目录就是为后者服务的。
3. **可复现性**。本目录每张图都有生成脚本，任何人都能用同一条命令复现出逐字节相同的图；他人论文的截图不具备这一性质，也无法在答辩中被追问"这个数怎么来的"。

## 2. 一键重新生成

```bash
# 在仓库根目录执行；默认输出到 assets/gallery，dpi=160，固定种子
python scripts/make_figures.py

# 投稿用高分辨率（论文要求 ≥300 dpi）
python scripts/make_figures.py --dpi 300

# 只重画某几张（按文件名子串匹配）
python scripts/make_figures.py --only sir
python scripts/make_figures.py --only evaluation

# 换一批合成数据（图形结构不变；换完请重新核对图注里的数值）
python scripts/make_figures.py --seed 12345

# 只跑数值自检，不出图（不需要 matplotlib）
python scripts/make_figures.py --self-test
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--out DIR` | `<仓库根>/assets/gallery` | 输出目录，不存在会自动创建 |
| `--dpi N` | `160` | 输出分辨率；内部限制在 72–600 之间 |
| `--seed N` | `20240517` | 只重抽合成数据，不改变图形结构；`--self-test` 不受它影响 |
| `--only SUBSTR` | 空（全部） | 只生成文件名含该子串的图 |
| `--self-test` | 关 | 打印 24 项数值内核的确定性自检结果 |

**环境要求**：Python 3.9+、`numpy`、`matplotlib`（本目录的图由 Python 3.13.5 / numpy 2.1.3 / matplotlib 3.10.0 生成）。脚本强制使用 `Agg` 非交互后端，可在无显示器环境运行。

**为什么这个脚本不放进 CI**：CI 只安装 `numpy`，**刻意不装 matplotlib**（省时间、避免无头渲染的不确定性）。因此脚本在导入失败时会自己给出人话报错并退出码 `2`，而不是抛一个 ImportError 堆栈：

```
[错误] 未检测到 matplotlib，无法生成配图。
       本脚本依赖 numpy + matplotlib；CI 刻意不装 matplotlib，
       因此请在本机执行：
           python -m pip install matplotlib numpy
       当前解释器：...
       原始错误：...
```

**确定性**：默认种子下，任意两次运行产出的 PNG **逐字节相同**（`optimization_convergence.png` 的收敛判据文字也由数据算出，不是写死的常数）。因此可以放心把 `assets/gallery/` 纳入版本管理。

## 4. 逐图说明

每张图给出：用途 / 坐标轴含义 / 要传达的结论 / 论文图注示例 / 常见错误。

> **关于图内标题**：目录里的图**都带图内标题**，这是为了让本页读者能单独看懂每张图。**投稿时请把标题从图内删掉、写进图注**（论文规范要求"图题在图下方，居中"），否则评审会认为排版不规范。删除方法：在各生成函数里去掉 `_finish(ax, "标题", ...)` 的第一个参数即可。

### 4.1 `evaluation_weights.png` —— 熵权 vs AHP 权重对比

- **用途**：在一张图里并列两套赋权结果，回答"权重从哪来、两套差多少"。
- **横轴**：8 项评价指标（类别轴，无量纲）。**纵轴**：指标权重 $w_j$ / %。
- **要传达的结论**：两种赋权法的结论**可以完全不一致**。本例熵权法把最大权重给了"经济性"（17.6%），把最小权重给了"维护成本"（7.9%）；AHP 恰好相反，给"维护成本"最大权重（17.4%）。
  所以权重不是中立的预处理，而是结论的一部分——必须交代来源，并在两法冲突时给出取舍理由。
- **论文图注示例**：

  > **图 3** 熵权法与 AHP 对 8 项评价指标的赋权结果对比。AHP 判断矩阵 $\lambda_{max}=8.112$，$CI=0.016$，$CR=0.011<0.10$，通过一致性检验。熵权法由指标数据离散度确定权重（最大 17.6%，最小 7.9%），AHP 由专家偏好确定权重（最大 17.4%，最小 5.2%），两者对"维护成本"的权重判断相反；正文 4.2 节采用熵权结果，理由见该节。

- **常见错误**：只画一套权重却不说是哪一套；用了 AHP 不报 $CR$（不做一致性检验的 AHP 等于拍脑袋）；把两套权重直接相加冒充"组合赋权"却不给依据；纵轴不写 `%` 或单位；条形图不排序，让读者自己找最大值。

### 4.2 `evaluation_topsis_rank.png` —— TOPSIS 贴近度与排序

- **用途**：给出最终排序，同时让读者看出名次之间的差距有多小。
- **横轴**：相对贴近度 $C_i$ / 无量纲（越大越优，范围 [0,1]）。**纵轴**：评价对象（已按 $C_i$ 降序排列）。条形末端标注数值与名次。
- **要传达的结论**：$C_i$ 的**绝对差距**比名次重要。本例 10 个方案的 $C_i$ 从 0.6194 递减到 0.3013，但第 1 名（0.6194）与第 2 名（0.6143）只差 **0.005**，第 8 名（0.4431）与第 9 名（0.4428）只差 **0.0003**。这两处排序实际上不可分辨，不能写成"方案 B 显著优于方案 A"。
- **论文图注示例**：

  > **图 5** 熵权-TOPSIS 法得到的 10 个方案相对贴近度 $C_i$（降序排列，$C_i\in[0,1]$，越大越优）。方案 B 与方案 A 的 $C_i$ 仅相差 0.005，该差异在权重 ±20% 扰动范围内不可分辨（见图 6），故本文只宣称方案 B 属于第一梯队，不宣称其优于方案 A。

- **常见错误**：把 $C_i$ 说成百分制"得分 87 分"（$C_i$ 是相对贴近度，不是分数）；不写权重来源；横轴不从 0 起却不在图中注明（截断坐标会放大差距）；只给名次表不给 $C_i$，读者无法判断差距是否显著。

### 4.3 `evaluation_weights_sensitivity.png` —— 权重扰动的排序稳健性

- **用途**：回答"我评出来的第一名，换个权重还是第一名吗？"——评价类论文最能体现工作量的一张图。
- **横轴**：扰动情景（16 列 = 8 个指标 × {+20%, −20%}，第 1 列为基准权重）。**纵轴**：10 个评价对象。**颜色**：综合排序名次 / 位（1 = 最优，10 = 最差），红虚线左侧为基准。
- **要传达的结论**：基准名次为 `[1,7,4,9,6,10,5,2,3,8]`；16 个单指标扰动情景中，**10 个方案里有 6 个至少变过一次名次，最大变动 2 位**。因此头部名次稳健、中段名次不稳健——这正是论文该写的精细化结论。
- **论文图注示例**：

  > **图 6** 单个指标权重 ±20% 扰动下各方案排序名次的变化。第 1 列为基准权重下的名次，右侧 16 列为逐指标扰动情景；色标 1 = 最优、10 = 最差。16 个情景中 6 个方案出现名次变动，最大变动 2 位，故第 1 名结论稳健，而第 4–9 名的相对排序不稳定，正文不据此给出"次优方案"推荐。

- **常见错误**：不做敏感性分析就宣布"最优方案"；只扰动一个指标就下"权重不敏感"的结论；色标方向搞反（务必在 colorbar 上写清 1 是最优还是最差）；扰动幅度（±20%）不说明取值依据。

### 4.4 `forecast_models_compare.png` —— 三模型外推与预测区间

- **用途**：多模型预测对比，并把"预测有多不准"一起画出来。
- **横轴**：期数 $t$ / 季度。**纵轴**：需求量 $y$ / 千件。实线为历史观测，竖虚线分隔拟合期与外推期，阴影为 95% 预测区间。
- **要传达的结论**：三种模型在近 8 期的 MAE 分别为 GM(1,1) **3.69**、Holt 线性趋势 **2.49**、二次趋势+季节因子 **1.07** 千件；第 8 步（$t=28$）三者分别外推到 73.1、62.8、63.8 千件，**分歧达 10.3 千件**。预测区间半宽随步长扩大：$h=1$ 时 8.14，$h=4$ 时 16.29，$h=8$ 时 **23.04** 千件——已经超过模型之间的分歧。所以 2 年以上的外推只能给区间，不能给点估计。
- **论文图注示例**：

  > **图 7** 三种模型对季度需求量的拟合与外推对比。实线为历史观测（$n=20$），虚线为外推值，阴影为二次趋势+季节因子模型的 95% 预测区间，半宽由第 1 步的 8.1 千件增至第 8 步的 23.0 千件。最后 8 期的 MAE：GM(1,1) 为 3.69、Holt 线性指数平滑为 2.49、二次趋势+季节因子为 1.07 千件。因第 8 步区间半宽已超过模型间分歧，本文只把 $h\le4$ 的外推值作为决策依据。
  >
  > 注：预测区间按近似法则 $1.96\hat\sigma\sqrt{h}$ 计算，未计入参数估计误差，实际区间可能偏窄。

- **常见错误**：只画模型线不画实测点（读者无法判断拟合好坏）；不报 MAE 或不画区间就给外推结论；用 20 期样本外推到 2050 年；阴影不说明是"置信区间"还是"预测区间"（两者含义不同）；不披露预测区间的计算方式。

### 4.5 `forecast_residual_diagnostics.png` —— 残差诊断四联图

- **用途**：证明模型"可用"，而不只是"误差数字小"。预测类论文里这张图往往比预测曲线更有说服力。
- **四个面板**：(a) 残差时序图：横轴期数 $t$ / 月，纵轴残差 $e_t$ / 千件；(b) 标准化残差正态 Q-Q 图：横轴理论分位数 $z_p$、纵轴样本分位数，均无量纲；(c) 残差分布直方图：横轴残差 $e_t$ / 千件，纵轴概率密度 / 千件$^{-1}$；(d) 残差 vs 拟合值：横轴拟合值 $\hat y_t$ / 千件，纵轴残差 $e_t$ / 千件。
- **要传达的结论**：$n=60$，残差标准差 2.945 千件，$t=26,38,48$ 三期超出 $\pm2\sigma=5.89$ 千件界限（最大 $|e|=6.68$）。Q-Q 图两端基本贴合参考线，残差 vs 拟合值无漏斗形——总体上支持"残差近似白噪声正态"，但三处离群必须交代来源。本例的数据是合成数据，离群点来自随机噪声项；换成真实数据时，这类离群通常是节假日、促销或统计口径变更造成的，**必须查明原因并在论文中说明**，不能默默忽略。
- **论文图注示例**：

  > **图 8** 模型残差诊断（$n=60$，残差标准差 2.945 千件）。(a) 残差时序图，未见趋势与周期结构；(b) 标准化残差正态 Q-Q 图，尾部基本贴合参考线；(c) 残差直方图与拟合正态密度对比；(d) 残差 vs 拟合值散点，未出现漏斗形，说明同方差假设可接受。$t=26,38,48$ 三期残差超出 $\pm2\sigma=5.89$ 千件界限，经核对为节假日效应，已在 4.3 节单独讨论并做剔除前后的对比。

### 4.9 `mechanism_param_sensitivity.png` —— 参数敏感性

- **用途**：机理模型必做的敏感性分析——"哪个参数最值得花力气控制"。
- **左图 (a)**：横轴时间 $t$ / 天，纵轴感染者比例 $I(t)$ / 无量纲，5 条曲线对应不同 $\beta$。**右图 (b)**：归一化蜘蛛图（基准 = 1.0），4 个轴为 4 项输出指标（峰值感染比例、累计感染比例、峰值出现时间、疫情持续时间），除黑色基准线外只有 3 条扰动线：$\beta$ +20%、$\gamma$ +20%、$S_0$ −20%。每个参数只取一个方向是刻意的——若 3 个参数各画 ±20% 就是 6 条线，极坐标图会糊成一团；取值方向也应在图注中说明（见下）。
- **要传达的结论**：$\beta$ 由 0.30 增到 0.54（$R_0$ 由 2.14 增到 3.86）时，峰值感染比例由 **0.182 升到 0.393**（+116%），达峰日由第 29 天提前到第 14 天。$\beta$ 只增加了 80%，峰值却增加 116%，弹性约 1.45。但**不要把这条结论读成"$\gamma$ 不重要"**：面板 (b) 中 $S_0$ −20% 使峰值下降 **40.7%**（弹性约 2.0），$\beta$ +20% 与 $\gamma$ +20% 使峰值分别变化 **+21.5% 与 −21.8%**，量级相当——因为峰值由 $R_0=\beta/\gamma$ 与 $S_0$ 共同决定，降低 $\beta$ 与提高 $\gamma$ 是同一件事的两面，结论应写成"压低 $R_0$ 比单独关注某个参数更有效"，并同时指出 $S_0$（初始易感比例）是本文模型中最敏感的量。
- **论文图注示例**：

  > **图 12** 参数敏感性分析。(a) 感染率 $\beta$ 取 0.30–0.54 天$^{-1}$（对应 $R_0$ 由 2.14 增至 3.86，$\gamma=0.14$ 天$^{-1}$ 固定）时的感染者比例曲线：峰值由 0.182 升至 0.393，达峰日由第 29 天提前至第 14 天；(b) 参数扰动 20% 的归一化蜘蛛图（基准情形 = 1.0；$\beta$、$\gamma$ 上调 20%，$S_0$ 下调 20%，4 个轴为 4 项输出指标），峰值感染比例对 $S_0$ 最敏感（−40.7%），$\beta$ 与 $\gamma$ 的影响量级相当（+21.5% 与 −21.8%），二者通过 $R_0=\beta/\gamma$ 共同决定峰值，故"压平曲线"应表述为降低 $R_0$。

- **常见错误**：只改一个参数却写成"全面敏感性分析"；蜘蛛图不做归一化（量纲不同无法同图比较）；敏感性只给曲线不给量化指标（弹性、极差、排序）；扰动幅度不说明依据。

### 4.11 `simulation_queueing.png` —— M/M/1 排队系统

- **用途**：排队/服务系统的理论—仿真互验，展示"高利用率下系统性能的非线性崩坏"。
- **左图 (a)**：横轴利用率 $\rho=\lambda/\mu$ / 无量纲（0.10–0.90），纵轴平均队长 $L$ / 辆。**右图 (b)**：横轴同为 $\rho$，纵轴平均等待时间 $W_q$ / min。两图均为理论曲线（实线）+ 仿真均值及 95% 置信区间（误差棒）。

- **论文图注示例**：

  > **图 14** M/M/1 排队系统性能指标随利用率 $\rho=\lambda/\mu$ 的变化（服务率 $\mu=6$ 辆/h，每个利用率点进行 12 次独立仿真、每次 500 位顾客）。(a) 平均系统队长 $L$；(b) 平均排队等待时间 $W_q$。实线为理论值（$L=\rho/(1-\rho)$，$W_q=\rho/(\mu-\lambda)$），点为仿真均值，误差棒为 95% 置信区间。$\rho=0.9$ 时理论 $L=9.0$ 辆、$W_q=90$ min，而仿真均值分别为 6.80 辆与 65.6 min，偏差源于临界附近的慢收敛，故实际运营建议 $\rho\le0.85$。

- **用途**：空间分布类问题的标准配图（气象、地质、人口、污染）。
- **坐标轴**：横轴东向坐标 $x$ / km，纵轴北向坐标 $y$ / km。**填色**为 IDW（$p=2$）插值降水量（等值线图，色标"年降水量 / mm"），**黑点**为 45 个虚拟雨量站，站点颜色用另一条色标"实测点降水 / mm"。
- **要传达的结论**：45 个站点的实测降水为 689.2–944.0 mm（极差 254.8 mm，均值 835.2 mm），IDW 插值场为 689.5–943.4 mm（极差 253.9 mm），等值线分层 675–950 mm。**IDW 是精确插值器，站点处插值结果等于实测值**，所以插值图"看起来总是很准"——真正的风险在站点稀疏区：那里没有任何观测支撑，等值线只是平滑外推。图中右下角已注明"插值不产生新的极值，峰值会被系统性平滑"。
- **论文图注示例**：

  > **图 18** 年降水量的空间分布（IDW 插值，幂次 $p=2$，140×112 规则网格）。黑点为 45 个雨量站的实测值（689–944 mm，均值 835 mm，极差 255 mm），填色为插值结果（13 层等值线，分层 675–950 mm，间隔约 23 mm；插值场极差 254 mm，比实测极差仅缩小 0.9 mm）。IDW 在站点处严格通过实测值，但站间区域仅为平滑估计；站点覆盖率约 0.56 个/(100 km)$^2$，故本文结论限定在站点 20 km 范围内，并用留一交叉验证报告插值误差（见 4.4 节）。

- **常见错误**：不写插值方法与参数（IDW 的幂次、Kriging 的变差函数、网格分辨率）；不写站点数与分布密度；不做留一交叉验证或误差评估就宣称"精度高"；用插值图的外推边界区域下结论（边界外推无数据支撑）；色标不分级或分级过少，掩盖空间差异。

### 4.16 `decision_radar.png` —— 多方案雷达图

- **用途**：少量方案 × 少量指标的直观对比。
- **坐标轴**：极坐标，6 条轴为 6 项指标（已正向化并归一化到 [0,1]，无量纲），每条折线为一个方案，图例标注加权得分。
- **要传达的结论**：4 个方案的加权得分分别为 A **0.494**、B **0.614**、C **0.710**、D **0.772**，D（混合式）最优、A（现状延续）最差。但雷达图上的面积是**相对值**，只能用于同一指标体系内的方案间比较，不能读成"得分 77.2 分"。
- **论文图注示例**：

  > **图 19** 四种方案在 6 项指标上的雷达图。各指标已按"越大越优"正向化并归一化到 [0,1]。加权得分：方案 A 0.494、方案 B 0.614、方案 C 0.710、方案 D 0.772（权重由熵权法确定）。图中分值为同一指标体系内的相对值，仅用于方案间比较，不代表绝对绩效水平。

- **常见错误**：指标方向不一致（有的越大越好、有的越小越好）而不做正向化；量纲不同不归一化；指标轴顺序随意排列（应按重要性或维度分组，且在图上标明顺序）；用图形面积宣称"综合得分"却不说明权重；指标超过 8 项仍用雷达图（应改条形图）；4 条以上折线叠在一起导致不可读（超过 5 个方案建议改分面小图）。

## 5. 通用绘图规范

以下是本目录所有图共同遵守的规范，也是数学建模论文配图的通行要求。

### 5.1 字体与字号

- **中文字体必须显式设置**，否则汉字会渲染成方框（`Glyph missing from font`）。本脚本使用：

  ```python
  plt.rcParams["font.sans-serif"] = ["Microsoft YaHei", "SimHei", "DejaVu Sans"]
  plt.rcParams["axes.unicode_minus"] = False   # 否则负号显示为方框
  ```

  脚本启动时会打印实际解析到的字体名（本机为 `Microsoft YaHei`）；若落到 `DejaVu Sans` 会给出装字体的提示（Windows：微软雅黑/黑体；Linux：`fonts-noto-cjk`）。
- **字号**：论文正文 10.5 pt（五号）时，**图内文字取 8–10 pt**，不得小于 7 pt。本脚本的 `rcParams` 设定为：全局 `font.size=9`、子图标题 10 pt、轴标签 9 pt、刻度标签 8 pt、图例 8 pt，图内注释按需取 7–8 pt。
- **同一个 `figure` 内字体大小一致**，不要因为某个标签太长就临时调小。

### 5.2 分辨率与格式

- **投稿要求 ≥300 dpi**（论文规范硬性要求）。本目录默认 `--dpi 160` 是为了让图片体积小、便于在网页/版本库中浏览；**交稿前请用 `--dpi 300` 重新生成**：实测总体积由 2262.6 KB 增至 4613.0 KB（约 2.0 倍），最大单张 457.3 KB，仍完全可用。
- **警告：`--dpi 300` 会触发脚本的"超过 250KB"提示**，因为该阈值是为默认的 160 dpi 预览图设的护栏，不是投稿限制。交稿时按 300 dpi 输出即可，忽略这条提示。
- 需要无损时改用矢量格式（PDF/SVG/EPS）插入 LaTeX；光栅图不要先用低 dpi 生成再放大。
- 本目录默认参数下单张图均控制在 **250 KB 以内**，最大一张 226.2 KB。

### 5.3 坐标轴与单位（最容易被扣分的地方）

- **两个轴都必须有量名和单位**，写作 `物理量 / 单位`（如"需求量 $y$ / 千件"）。无量纲量也要写明"无量纲"。
- 刻度方向、对数坐标、截断坐标要在图上注明（对数轴必须写"（对数坐标）"）。
- 坐标范围不要"自动"，尤其是条形图：截断纵轴会夸大差异，若必须截断要加断轴标记。

### 5.4 明确禁止的几种画法

- **禁止 3D 饼图**，也尽量避免任何 3D 效果（透视会扭曲面积与角度，读者无法比较）。
- **禁止滥用双 Y 轴**。两条曲线量纲不同时，双 Y 轴的交叉点没有任何物理意义，却极易被误读为"关键转折"。正确做法是**拆成上下两个面板**（本目录 `simulation_queueing.png` 就刻意采用了双面板而非双 Y 轴）。
- 禁止用饼图表示趋势，用折线表示构成。
- 禁止红绿对比配色（约 8% 的男性无法区分）——本目录统一使用 **Okabe-Ito 色盲友好调色板**。

### 5.5 误差与不确定性必须标注

- 凡是有随机性的结果（仿真、抽样、重复实验），**必须给出误差棒或置信区间，并说明是标准差、标准误还是 95% 置信区间**（三者含义完全不同）。
- 预测类结论必须带预测区间；区间须说明计算方法（本目录的预测区间用近似法则 $1.96\hat\sigma\sqrt{h}$，已在图注中披露）。
- 误差棒要写清 $n$（重复次数）。

### 5.6 图注（caption）要自解释

- 图题置于**图的下方、居中**；图注应说明：画的是什么、数据来源/样本量、关键参数、图中标注的含义。
- 图注应当让读者**不读正文也能看懂这张图**。
- 建议在关键结论处直接在图上标注（如"峰值 $I_{max}=0.304$，出现于第 19 天"），减少读者在正文与图之间来回跳的次数。
- **投稿时删除图内标题**：本目录为便于浏览保留了图内标题，论文中标题应移到图注（见第 4 节开头的说明）。
- 使用合成/示意数据时，图注必须注明"示意图，数据为合成数据"。

### 5.7 风格统一

同一篇论文内的图应统一：配色方案、字号、线宽、图例位置风格、网格线样式。本目录的图共用同一套 `rcParams` 与调色板，因此放在一起不会"五颜六色"。

## 6. 图必须被正文引用

论文中的每一张图都必须在正文里被提到，并按顺序编号。只放图不引用，评阅时会被视为"图表堆砌"或排版不规范。

- 正确：`……结果如图 5 所示，方案 B 的相对贴近度为 0.619，居首位。`
- 正确（引出多张图）：`……分别见图 6 与图 7。`
- **不要**只写"如下图所示"（正式论文中避免"如下图/上图"这类相对表述，直接用"如图 X 所示"）。
- 图号、表号在全文内统一编号（图 1、图 2……），不要与公式号混用。
- 建议顺序：正文提到某图之前，该图不应先出现；图应尽量靠近首次引用它的段落。
- 引用图的同时**要给出结论**，而不是让读者自己去图里找。例如不要写"评价结果见图 5"，而应写"评价结果见图 5，方案 B 的相对贴近度为 0.619，居首位，但与方案 A 仅差 0.005，差异不显著"。

## 8. 自检与校验

```bash
# 数值内核自检（24 项，固定种子，确定性）
python scripts/make_figures.py --self-test

# 重生成并检查每张图是否非空白
python scripts/make_figures.py
```

`--self-test` 会打印权重、TOPSIS、GM(1,1)、Holt、SIR、K-means、Dijkstra、IDW、M/M/1 等内核函数的小规模确定性结果（如 `ahp_cr 0.011333`、`sir_peak_infected 0.303811`、`silhouette_mean 0.758441`），可用于确认环境与算法实现未变。

正常生成时脚本会逐张打印耗时、体积、像素尺寸与像素标准差，并在末尾汇总；若某张图的像素标准差 ≤ 0.005，会以"疑似空白图"标记并把退出码置为 1。**任一图绘制失败（例如少了模块）都不会静默跳过**。
