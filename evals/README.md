# 触发评测用例（description 与触发率）

用途：验证这个技能的 **description 是否能在正确的时机被触发**，以及**是否会在不该触发时误触发**。

评测方法依据 Agent Skills 官方 description 优化指南：造约 20 条查询，跑多次统计**触发率**，并以 near-miss 反例作为最有价值的负例。

---

## 怎么用

1. 对每条 `query`，在**未加载本技能**的干净会话里提问，记录技能是否被触发（`skill` 工具被调用 / 技能内容进入上下文）。
2. 每条**重复 3 次**（模型有随机性），触发率 = 触发次数 / 3，阈值取 **0.5**。
3. 统计：
   - `should_trigger: true` 的用例触发率应 ≥ 0.5（越高越好）
   - `should_trigger: false` 的用例触发率应 ≤ 0.5（越低越好）
4. 分 **train / validation** 两组（约 60% / 40%）：只根据 train 的失败修改 description，用 validation 检验是否真的变好——**防止把 description 过拟合到评测集**（官方明确点名这个反模式：不要把失败用例里的具体关键词硬塞进 description）。
5. 第 4 步是**基线对照**：同一批用例在"无技能"状态下本来就答得好的（如"什么是灵敏度分析"），不应作为改进依据。

---

## 负例为什么重要

弱负例（例如 "Write a fibonacci function"）几乎不会误触发，**测不出问题**。
真正有价值的是 **near-miss**：与技能领域共享关键词、但实际是别的任务——例如"帮我用 Python 拟合一条曲线"（是编程任务，不是竞赛论文任务）、"解释一下 ARIMA 模型"（是概念问答）。

用例清单见 `evals/trigger-queries.json`。
