# 论文结构与写作规范

论文是唯一交付物——模型再好，写不清楚就等于没做。本文件给章节骨架、篇幅配比、每章"必须出现什么"与常见写法错误。

---

## 一、国赛 / 研赛（中文论文）章节骨架

国赛规范要求：**第 1 页承诺书、第 2 页编号专用页、第 3 页摘要专用页（页码从摘要页开始）、第 4 页起正文，正文不要目录、不超过 30 页，之后为附录（页数不限）**。电子版则**不含**承诺书与编号页，首页必须是摘要页。

| 顺序 | 章节 | 必须出现的内容 | 建议篇幅（30 页正文内） |
|---|---|---|---|
| 0 | 标题 | 具体、含研究对象与方法（避免"关于某问题的研究"这类空标题） | — |
| 1 | 摘要 + 关键词 | 每问的模型、方法、**具体结果**、检验结论、创新点 | 1 页（独占） |
| 2 | 一、问题重述 | 用自己的话概括背景与待求问题，分问列清 | 1–2 页 |
| 3 | 二、问题分析 | 每问的思路、为什么这样建模、整体技术路线图 | 2–3 页 |
| 4 | 三、模型假设 | 3–8 条，每条说明依据 | 0.5–1 页 |
| 5 | 四、符号说明 | 表格：符号 / 含义 / 单位 | 0.5–1 页 |
| 6 | 五、模型建立与求解 | 分问展开：模型形式（公式）→ 求解方法 → 结果 | 10–15 页（主体） |
| 7 | 六、结果分析与检验 | 误差分析、与基线/其他方法对比、模型检验 | 3–5 页 |
| 8 | 七、灵敏度分析 | 关键参数扰动对结论的影响 | 2–3 页 |
| 9 | 八、模型评价与推广 | 优点、缺点、适用条件、可推广场景 | 1 页 |
| 10 | 参考文献 | 按科技论文规范列出，正文有 `[n]` 标注 | 0.5–1 页 |
| 11 | 附录 | **支撑材料文件列表** + **全部完整可运行源程序**（含 Excel/SPSS 交互命令） | 不限 |

> 若未使用程序，必须在附录写明"本论文没有用到程序"；若无支撑材料，注明"本论文没有支撑材料"。规范原文：**缺少必要的源程序、程序不能运行或运行结果与论文不符，都可能会被取消评奖资格。**

### 章节标题样例（可直接改写使用）

```text
一、问题重述
  1.1 问题背景
  1.2 待解决的问题
二、问题分析

```

## 一之二、获奖论文章节出现率（实证：2021–2025 年 64 篇国赛获奖论文）

来源：社区对获奖论文全文的 OCR 统计（**非官方**，但这是目前唯一带分母的结构数据，比"拍脑袋"可靠）。

| 章节 | 出现率 | 解读 |
|---|---|---|
| 参考文献 | 98% | 几乎必备 |
| **符号说明** | **94%** | **比摘要还高**——中文建模论文的默认必备件 |
| 摘要 | 92% | |
| 附录 | 92% | |
| **问题分析** | **91%** | 不是可选项，是主流做法 |
| 问题重述 | 83% | |
| 模型假设 | 83% | |
| 关键词 | 80% | |
| 模型的建立与求解 | 72–90% | 正文主体 |
| **模型评价** | **28%** | **不是国赛的刚性章节** |
| 模型检验（独立成章） | 23% | 多数并入"建模与求解" |
| 灵敏度分析（独立成章） | 19%（含该内容约 36%） | 同上 |

**三条可操作结论**：

1. **默认写"符号说明"表**——它出现率比摘要还高，是事实标准。
2. **检验与灵敏度不必独立成章**：写进每一问的求解结果之后即可（多数获奖论文的做法）；但**内容必须存在**——只给结果不做检验仍是失分点。
3. **模型评价是国赛的可选章节，却是美赛的必备章节**（美赛官方点名要求 strengths and weaknesses）。这是两类竞赛最明显的结构差异之一，**不要把国赛结构套到美赛**。

> 数据仅覆盖国赛；研赛的同类语料统计未找到。

## 二、MCM/ICM（英文论文）章节骨架

| 顺序 | 章节 | 要点 |
|---|---|---|
| 0 | **Summary Sheet**（单独成页，置于全文最前） | 评审第一入口：背景 → 每问模型与方法 → 量化结果 → 灵敏度 → 建议；250–400 词 |
| 1 | Introduction / Background | 复述问题（restatement）要**体现理解深度**，不要照抄题目 |
| 2 | Assumptions and Justifications | 每条假设必须给理由；美赛评审非常看重这一节 |
| 3 | Notations | 表格形式；符号量控制在可管理范围 |
| 4 | Model Development | 分问展开；说明**为什么选这个模型**、替代方案为何不选 |
| 5 | Results / Model Application | 结果 + 图表 + 与实际意义的解释 |
| 6 | Sensitivity Analysis / Robustness | 几乎每篇 O 奖论文都有；参数扰动 + 结论稳定性 |
| 7 | Strengths and Weaknesses | 诚实的自我评估（不要只写优点） |
| 8 | Conclusion | 面向决策者的可执行建议 |
| 9 | References | 规范引用；网上资料也要列 |
| 10 | Appendix / Memo | 代码、补充推导；有些题型要求写 Memo/Letter |

**美赛与国赛的关键差异**：
- 语言必须英文，且**语言质量本身影响评级**（语法错误多会被压等级）。
- 强调 **assumptions 的合理性论证**、**模型选择的justification**、**sensitivity analysis**、**strengths/weaknesses**。
- Summary Sheet 的分量极重——很多评委主要据此分级。
- 允许（并在近年政策中要求申报）AI 工具使用，须遵守 COMAP 当年规定（见 `references/contests.md`）。

## 三、每一章"必须出现"的硬清单

**问题分析**：一张技术路线图（流程图）。评委靠它 10 秒判断你是否想清楚。

**模型建立**：
- 数学表达式（公式编号），不能只有语言描述
- 变量含义与取值范围的解释
- 模型适用条件与局限的一句话说明

**模型求解**：
- 算法名称、关键参数、软件与版本
- 复杂度或计算量说明（大规模问题时）
- 结果表/图（有单位、有精度说明）

**结果分析**：
- 与至少一个**基线**对比（现状方案 / 贪心 / 简单模型 / 文献结果）
- 误差指标与解释（为什么误差是这个量级）
- 结果的实际意义（给谁用、怎么用）

**灵敏度分析**：
- 选哪些参数：对结果影响最大的 2–4 个
- 扰动范围与依据（±10%/±20%，或按数据精度）
- 结论句："当 X 在 [a,b] 内变动时，Y 变化不超过 Z%，模型稳健"或"Y 对 X 高度敏感，实际中需精确测量 X"

**模型评价**：优点 3 条以上、缺点 2 条以上。缺点要诚实但不能自我否定——写成"局限与改进方向"。

## 四、写作技术规范

- **公式**：用公式编辑器或 LaTeX；编号 `(1)(2)`；跨页公式尽量避免；变量用斜体，单位用正体。
- **图**：图题在图下方，居中；坐标轴带量名与单位；≥300 dpi；图内文字与正文字号协调；同一论文风格统一（配色、线型）。
- **表**：表题在表上方，居中；三线表；单位写在表头或栏头；有效数字位数一致。
- **引用**：正文用 `[1]`、`[1,3]`、`[2-4]`；参考文献按规范格式（作者. 题名. 出处, 年份, 卷(期): 页码.）；**网上的资料也必须列出**（规范第七条要求）。
- **代码**：附录给出可直接运行的完整脚本，标注运行环境与依赖版本；不要贴截图。
- **术语**：全文统一（"配送中心"不要一会儿写成"仓库"）；首次出现的缩写给全称。
- **时态/人称**（英文）：描述模型用现在时，描述所做工作用过去时；避免 "I"，用 "we" 或被动语态。

## 五、写作顺序（省时间的实战顺序）

1. 建模与求解跑通，结果落盘（CSV/JSON）。
2. 先画**技术路线图**——它逼你把逻辑理顺，也是问题分析章节的核心。
3. 写建模与求解章节（对着代码与结果写，不要凭记忆）。
4. 写结果分析、灵敏度、模型评价。
5. 补问题重述、问题分析、假设、符号说明（这些写作时最省脑力，放后面）。
6. **写摘要**（此时所有数字都已固定）。
7. 通读一遍，做符号一致性、数值一致性检查；跑 `scripts/check_paper.py`。
8. 对照 `references/checklists.md` 逐项确认后再提交。

> 留出至少 15% 的总时间给写作与检查。建模再漂亮，最后 2 小时赶出来的论文也拿不到高奖。
